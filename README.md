# Funban

Планировщик на неделю для команды из пяти человек: цель спринта, входящие со скринами, бэклог со своими критериями, комментарии.

```bash
npm install
npm run dev
```

Откройте http://localhost:5173. Состояние пишется в `data/state.json` — одна доска на всех, кто открыл этот адрес в сети.

## Проверка в превью Codex

`npm run preview:checks` собирает приложение и запускает изолированный production entrypoint на временных данных. Откройте `http://127.0.0.1:4330/__test/preview` внутри превью Codex: кнопка запускает проверки API и объединения изменений прямо в браузере. Кнопка подготовки сценариев создаёт одноразовую доску для ручной проверки, включая удаление задач. На панели можно имитировать отказ записи, задержки и параллельные правки. Внешняя аналитика отключена. Данные рабочей доски и production не используются.

Тестовый прокси и команды сброса находятся только в `tests/e2e-server.mjs`; `server.mjs` не предоставляет эти маршруты. E2E использует тот же сервер и репозиторий, что production. Временные файлы состояния, метаданные и журнал очищаются при сбросе сценария.

## Постановка задач из Claude и Codex

### Доступ к доске

В production страницы, API доски и вложения доступны только с действующей сессией Team Portal. Funban проверяет cookie через внутренний `http://team-portal:3000/api/access/identity`; при недоступности портала доступ закрывается. На прокси домен также закрыт Portal ForwardAuth. Отдельный пароль Funban не нужен. Вход и возврат на доску: `https://future-db.ru/open/funban`.

Публичный URL должен быть указан в `FUNBAN_PUBLIC_URL`, а HTTPS завершаться на доверенном reverse proxy. `/api/health` остаётся доступным для мониторинга, `/mcp` защищён отдельным Bearer-токеном. Не сохраняйте токены в Git.

Личность берётся из портала автоматически: экрана выбора участника и кнопок «Это я» нет. Сервер подписывает новые задачи, комментарии и реакции подтверждённой учётной записью. Исторические авторы и пять участников доски сохраняются отдельно; учётная запись портала не назначается произвольно одному из них. `localStorage` и входящие identity-заголовки не дают прав и не меняют автора.

`FUNBAN_PORTAL_IDENTITY_URL` и `FUNBAN_PORTAL_LOGIN_URL` позволяют настроить адреса портала для отдельного окружения. В production проверка сессии обязательна даже без этих переменных. Локальная разработка без `NODE_ENV=production` использует тестовую личность; не публикуйте dev-сервер в интернете. Превью и E2E запускают production-сервер с изолированным тестовым порталом и синтетическими cookie.

Поиск в шапке ищет по названию и описанию во всех разделах, включая архив. При завершении сессии интерфейс закрывается и предлагает общий вход; несохранённые правки остаются в локальном черновике.

После деплоя production-сервер поднимет удалённый MCP endpoint `https://funban.future-db.ru/mcp`. Он умеет:

- показывать участников, недели и критерии оценки;
- искать задачи перед созданием дубля;
- создавать и редактировать задачи;
- назначать участника по имени;
- ставить двусторонние связи между задачами.

MCP не умеет удалять задачи, закрывать спринт или перемешивать роли. Каждая запись имеет `requestId`, поэтому повторная отправка одного запроса не создаёт дубль. Изменения пишутся атомарно, а журнал операций хранится рядом с файлом состояния.

### Сервер

Нужен один общий токен команды — персональные токены не используются. Сам токен в репозиторий не добавляется:

```bash
export FUNBAN_MCP_TOKEN='общий-токен-команды'
export FUNBAN_PUBLIC_URL='https://funban.future-db.ru/'
export FUNBAN_TIME_ZONE='Europe/Moscow'
npm run build
npm start
```

Если reverse proxy меняет HTTP-заголовок `Host` на внутреннее имя, добавьте его через `FUNBAN_ALLOWED_HOSTS` (несколько имён разделяются запятыми). Публичный домен и localhost разрешаются автоматически.

Если сайт целиком закрыт HTTP Basic Auth на reverse proxy, для `/mcp` нужно отключить Basic Auth и оставить проверку Bearer-токена приложением. Иначе Claude и Codex не смогут передать оба способа авторизации в одном заголовке.

### Codex

```bash
export FUNBAN_MCP_TOKEN='общий-токен-команды'
codex mcp add funban \
  --url https://funban.future-db.ru/mcp \
  --bearer-token-env-var FUNBAN_MCP_TOKEN
```

### Claude Code

```bash
export FUNBAN_MCP_TOKEN='общий-токен-команды'
claude mcp add --transport http --scope user funban \
  https://funban.future-db.ru/mcp \
  --header "Authorization: Bearer $FUNBAN_MCP_TOKEN"
```

### Один раз в начале личного чата

Напишите, например:

> В Funban по умолчанию создавай задачи на Лилю. Если я явно назову другого участника — назначай ему.

После этого можно писать обычным языком: «Добавь в бэклог задачу про новый онбординг и оцени по критериям». Имя, явно указанное в такой постановке, всегда имеет приоритет над исполнителем по умолчанию. Общий токен только даёт доступ к доске и сам по себе не определяет автора или исполнителя.

Перед созданием каждой задачи агент обязан сам искать на доске дубли, родительские инициативы и смысловые зависимости. Отдельно просить «найди и добавь связи» не нужно: найденные релевантные задачи связываются автоматически по точным id. Пустой список связей допустим только после поиска, если подходящих задач действительно нет.
