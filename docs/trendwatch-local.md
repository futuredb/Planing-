# Трендвотч во входящих: локальная первая версия

Актуально с 27.11.2026: все ИИ-запуски только вручную. Описанные ниже исторические проверки автоматической оценки и уточнения при вводе не означают, что эти функции сейчас включены. Сервер блокирует их даже при старом `FUNBAN_TRENDWATCH_AUTO=1`.

## Уточнение объяснения приоритета — 27.11.2026

Общий промпт Codex и OpenRouter оценивает пользу следующего результата задачи. Завершённый эксперимент не должен становиться обязательным условием высокого приоритета задачи, которая этот эксперимент готовит. Условие повышения балла — существенное входное основание: например, масштаб проблемы, потребитель результата, возможность применения или срок. Неизвестные ресурсы не означают низкую пользу. Внешние эффекты остаются результатами конкретного источника, а перенос на наш продукт — гипотезой.

Контрольные случаи из предыдущих обсуждений (ручной разбор правил, не новые ответы модели):

| Задача | Что должно измениться в объяснении |
| --- | --- |
| «Чаевые. Композиция» | Не требовать готового A/B для повышения приоритета подготовки композиций. Не смешивать сумму чаевых, средний чек и выручку; не обещать эффект чужого эксперимента. |
| Автоматизация сбора материалов | Подтверждённые 2 часа в неделю с учётом проверки дают 8 часов за четыре недели. Не умножать на неизвестное число сотрудников и не переводить в деньги без ставки. |
| Продажи цифровых дизайнов, conjoint | Оценивать пользу решения о свойствах и цене без подстановки категории продукта и требования уже доказанных продаж. |
| Синтетические респонденты | Оценивать пользу проверки нового подхода, включая отрицательный вывод; не требовать заранее доказанной заменимости живых участников. |

Сравнение должно называть конкретное основание очередности. Фраза «обе задачи полезны» не доказывает равный приоритет; при недостатке сведений используется `insufficient`. Равные баллы допустимы. Числа остаются порядковым суждением, а не вычисленной точностью.

Формат ответа, шкала, проверки источников, интерфейс и подтверждение лида не изменены. Существующие рекомендации и сохранённые оценки не пересчитываются. Регрессионная проверка проверяет передачу правил провайдеру в обоих разделах и режимах; качество реального ответа после этой правки ещё требует отдельной ручной проверки.

## Интерфейс

В «На разбор» над кнопками переноса находится розово-перламутровая кнопка со звёздами и оценкой, размером 88 × 36 CSS px, одинаковым с кнопками «В спринт» и «В бэклог». Нажатие открывает окно «Рекомендация ИИ»; саммари и форма оценки не занимают место в списке. Если оценки нет, показано «—»; при обработке — «…», при изменении контекста неподтверждённый балл скрыт. Подтверждённый балл сохраняется; через 30 дней окно предлагает пересмотр. Открытие окна не запускает модель. Escape, крестик и нажатие вне окна закрывают его; редактирование остаётся черновиком до подтверждения. Постоянный перелив отключается при prefers-reduced-motion. Существующие переносы, ручная оценка, авторы, исполнители, реакции и загрузка файлов сохранены.

## Ручной запуск рекомендации через Codex — локальный режим по умолчанию

`npm run dev:local` включает `FUNBAN_TRENDWATCH_MODE=codex`. Нужен установленный Codex CLI с входом через ChatGPT (`codex login status`). В текущем окружении обнаружена версия `0.167.0-alpha.3.2`; реальный ответ модели проверен локально 12.11.2026 на задаче AI-исследователя: короткий ответ и балл получены, человеческое подтверждение не выполнялось. Результаты без веб-поиска проверялись на AI-исследователе и conjoint-задаче; это отдельные примеры, не оценка качества на всём бэклоге.

Во входящих: заполнить название и описание → «Получить ИИ-рекомендацию» → прочитать 2–3 предложения → подтвердить или изменить один балл 0–10. Дополнительных полей аудитории, цели, географии, критериев и комментария нет. Горизонт новых оценок — ближайшие 30 дней. Статусы: «Рекомендую», «Проверить гипотезу», «Пока отложить». Расшифровка критериев свёрнута под «Как рассчитано». Ручная передача файлов не нужна. Для уже готовой рекомендации доступно «Повторить анализ». Автоматический первый разбор и уточнения при вводе отключены, в том числе при старом `FUNBAN_TRENDWATCH_AUTO=1`. Локальный preview использует `AUTO=0` по умолчанию. Повторный разбор — отдельное явное нажатие; один процесс за раз, до 5 минут. Отмена и перезапуск сервера останавливают обработку; поздний ответ не меняет задачу.

Сервер запускает `codex exec` с существующей ChatGPT-авторизацией, коротким исследовательским заданием и JSON Schema. Это отдельный вызов Codex после нажатия пользователем кнопки анализа, не управление текущим окном чата. Он использует лимиты аккаунта ChatGPT/Codex; это не локальная модель и не обещание бесплатной обработки. Данные задачи и выбранные фрагменты отправляются OpenAI. OpenRouter и API-ключи проекта не используются.

Короткий формат `quick-v1` использует задачу и автоматически подобранный контекст доски. До 40 других задач: сначала похожие по словам в названии/описании, с резервом для бэклога, выполненного и архива (по 5). Передаются ID, название (до 200 символов), описание (до 400) и статус. Авторы и вложения не передаются. В concept-mvp-v1 с regional-signals-v4 также используются комментарии самой оцениваемой задачи (лимиты ниже); комментарии соседних задач не передаются. Подбор лексический, а не семантический поиск всей истории; размер выборки доступен в записи запуска. Модель возвращает до трёх похожих задач с пояснениями, сервер проверяет существование ID в переданном снимке. Ссылки открывают обычный инспектор задачи.

`done` означает «Выполнено», `archive` — только «В архиве»: исторические данные не сохраняют надёжно причину архивирования. Нельзя заявлять о завершении или эффекте только по архивному статусу.

До трёх сохранённых источников добавляются по 2500 символов. **Локальный preview теперь включает лёгкий веб-поиск** (`FUNBAN_TRENDWATCH_WEB=1`); `FUNBAN_TRENDWATCH_WEB=0` возвращает прежний режим без поиска. На обычном сервере флаг по умолчанию выключен. Старые рекомендации не меняют свой режим задним числом. Без внешних источников предварительная оценка должна явно обозначать недостаточность оснований. Балл — рекомендация о приоритете, не вероятность успеха или доказанный прогноз рынка. Полный исследовательский workflow не запускается. Старые отчёты не переписываются, отсутствующий в них общий балл не придумывается.

CLI получает отдельный временный каталог, read-only sandbox, отключённые shell/browser/apps/MCP через отключение приложений и игнорирование пользовательской конфигурации, отключённые multi-agent, hooks и image tools. Только для новых запусков с флагом webSearch разрешён встроенный веб-поиск в режиме live с небольшим контекстом. В установленной версии модели используют code_mode_only: для доступа к поиску включены изолированный code-mode host и standalone_web_search. Отключённый host оставлял модель без инструментов, несмотря на live; shell и приложения при этом остаются отключёнными. Передаются только базовые переменные окружения; API-ключи не наследуются. Пользовательские строки идут через stdin, не shell. Настройки и авторизация пользователя не переписываются. Ответ ограничен по размеру: саммари до 500 символов, балл 0–10, до трёх связанных задач. Проверяются схема, ID пакета и ссылки на задачи из снимка. Подтверждение сохраняет только обоснованно оценённые критерии и выбранный итог, оставляя задачу в текущей колонке. Перенос выполняется отдельной кнопкой «В бэклог» или «В спринт».

Тесты используют явно синтетический CLI `tests/fixtures/codex-cli.mjs`; они проверяют процессы и интерфейс, но не доказывают качество модели или успешность реального удалённого ответа. Отдельный `FUNBAN_CODEX_BIN` задаёт путь к исполняемому Codex только из конфигурации сервера.

Официальная документация: [non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [authentication](https://learn.chatgpt.com/docs/auth).

Данные сохраняются в `data/local-development/lifecycle-demo/state.json`; `FUNBAN_LOCAL_PORT` и `FUNBAN_LOCAL_DATA` позволяют явно выбрать другое окружение. Копии на 4334 и 4336 остановлены, их данные сохранены. На 4342 остаётся только краткая презентация со ссылкой на Funban, не вторая доска. Аналитика, MCP и тестовые управляющие маршруты отключены. Портал обращается только к локальному mock-серверу.

Для ручного режима задайте `FUNBAN_TRENDWATCH_MODE=assisted`. Этот режим не импортирует Trendwancher, не читает его `.env` и не запускает поиск или модели. Приложение подготавливает задание и принимает результат; сам анализ выполняется в чате по явному запросу пользователя. Автоматической связи браузерной кнопки с чатом нет.

Ручной импорт сохранён для совместимости на API: POST `/api/items/:id/trendwatch` → GET `/packet?jobId=…` → POST `/review`. Старый формат с цитатами и критериями по-прежнему валидируется. Ручные кнопки передачи файлов убраны из интерфейса по требованию упрощённого сценария. Для кнопки автоматической рекомендации используйте режим `codex`.

## Предыдущий автоматический режим — только явное включение

Платный режим оставлен для совместимости, но не запускается командой `npm run dev:local` по умолчанию. Для его включения нужен `FUNBAN_TRENDWATCH_MODE=runtime`, Node.js 24+, `FUNBAN_TRENDWATCH_ROOT` с зависимостями и настроенным `.env` (или `FUNBAN_TRENDWATCH_ENV_FILE`). При явном выборе runtime локальный скрипт проверяет импорт и наличие настроек без сетевого запроса. Сам запуск исследования может обращаться к внешним API.

### Реальное подключение и границы автоматического режима

`trendwatch-worker.mjs` импортирует `src/research.js:runResearch`, `AgentTeam`, аудит и бюджет из установленного Trendwancher. Используется adaptive workflow с проверкой свидетельств; Telegram-бот не запускается. Версия брифа — 7, исследовательская рамка — desk research. Дополнительное обращение к аналитику переводит проверенные выводы в рекомендацию по текущим критериям Funban. Ответ проверяется по схеме, ссылки собираются из фактически полученных свидетельств; ссылки, придуманные моделью, не принимаются.

Сервер и процесс исследования работают локально. Настоящее исследование обращается к настроенным внешним поиску и моделям и может расходовать их лимиты. Отправляются название, описание и введённый контекст одной задачи. Вложения, соседние задачи, состав команды и комментарии в исследование не передаются. Пользователь запускает каждый прогон явно.

Один процесс за раз; до 15 минут, 6 заданий сбора, 8 источников, 60 обращений модели и 120 000 токенов исследовательского бюджета. Сохраняется ограничение OpenRouter: меньшая величина из настройки проекта и $2 на запуск. Это **не общий денежный лимит**: поиск и GigaChat учитываются отдельно. Неизвестные расходы не считаются нулевыми. Повторный запуск после завершения/отмены — новая попытка с отдельным бюджетом, без автоматических повторных исследований. Нет заявлений о гарантированной полноте или точности прогноза.

Первая версия собирает веб-источники. Автоматический сбор отзывов, медиа, скриншотов, презентации и полное исследование всех каналов не включены. Недостаток материалов должен приводить к явно ограниченной рекомендации или состоянию «недостаточно данных». Остановка по лимиту планирования объясняется отдельно: это не требование уточнить задачу. Для архивных запусков причина восстанавливается из `run.json`, исходный файл не перезаписывается.

## Данные и защита

- Исследования хранятся отдельно: `<FUNBAN_DATA>.trendwatch/<job-id>/`. Каталог исключён из Git; исходные отчёты и аудит остаются локально. Права каталога — только для владельца.
- Только в режиме runtime секреты читаются в дочернем процессе из `.env` Trendwancher; в браузер, ответы API и репозиторий они не попадают. Выбираются только настройки провайдеров и агентов, без Telegram.
- Пользовательские строки не попадают в командную оболочку. Путь к модулю задаёт локальная конфигурация сервера, а не запрос браузера.
- Повтор одного запроса не создаёт второй процесс. Конкурентные запуски ограничены; отмена завершает процесс. После перезапуска сервера незавершённый запуск обозначается как прерванный и автоматически не возобновляется.
- Снимок исследования включает описание, текущие оценки, колонку и критерии; в `quick-v1` — также выбранный контекст доски. Изменение этих данных запрещает принятие устаревшей рекомендации на сервере. Исключение — собственное подтверждение: сервер сохраняет в защищённой записи решения отпечаток состояния после него; это позволяет повторно менять балл без нового запуска, но не принимать ответ после изменения описания или использованного контекста доски.
- Подтверждение выполняется отдельным аутентифицированным API. Сервер записывает автора из сессии, время, оценку и ID исследования. Компактный POST `/confirm` принимает `{requestId, jobId, score}`. Совместимость со старым контрактом подтверждения сохранена. Обычное сохранение доски не может подделать эту запись.
- Исследование не меняет данные доски. Только человеческое подтверждение изменяет оценки и статус. Решение и ссылки на отчёт доступны во вкладке «Оценка» инспектора.

## Хранение оценки и обратимость

В архивных business-v2/business-v3 рекомендациях подтверждённый единый балл хранится в `Item.priorityScore` и используется в общей сортировке/отображении вместо формулы. Старые `scores` остаются без изменений; для задач без `priorityScore` работает прежняя формула. Оценку можно изменить во вкладке «Оценка» инспектора; запись о первоначальном подтверждении сохраняется. Компактное подтверждение сохраняет оценку и запись о решении; статус, колонка и спринт не изменяются. Кнопка становится «Подтверждено», но оценку можно отредактировать и подтвердить ещё раз. Перенос в бэклог или спринт выполняется отдельно. Старый контракт API с критериями сохраняет прежнее поведение для совместимости. Миграции и пересчёта исторических задач нет. Для отката к прежней формуле потребуется явно удалить новый балл, сохранив старые критерии; это не автоматическое действие.

## Проверки

```sh
npm run test:trendwatch
npm run test:mcp
npm run test:e2e
npm run lint

```

Модульные тесты проверяют сохранность оценок, конкурентные/повторные запросы, устаревание, отмену, восстановление после перезапуска, недостоверные ответы и подтверждение. Браузерные тесты проходят через настоящий HTTP-сервер, дочерний процесс и адаптер, используя явно синтетические исследовательские модули из `tests/fixtures/trendwatch`. Они не обращаются к настоящим провайдерам и не доказывают содержательное качество реального исследования.

Реальный платный прогон — отдельная проверка на согласованной задаче и бюджете. Её результат оценивается по цепочке «задача → собранные источники → проверенные выводы → рекомендация», отдельно от технических тестов.

## Проверка на сохранённом запуске AI-исследователя

12 ноября 2026: автоматический запуск остановился до анализа (`planning_token_budget`). В архиве есть две страницы поставщиков: Miro и Paperguide; нет принятых свидетельств и измеренного эффекта для команды. Короткий разбор в чате должен предложить проверку рабочего сценария, обозначить неизвестную перспективность и оставить баллы пустыми. Заявления поставщиков не становятся подтверждением роста спроса или будущей экономии времени. Оригинальный платный запуск и его бюджет не возобновляются и не переписываются.

Служебные элементы Codex `error` не считаются вызовом инструмента: сохраняются только обезличенные категории диагностики, решение об успехе зависит от `turn.completed`, кода завершения и валидного JSON. Все инструменты кроме явно включённого web_search по-прежнему останавливают короткий разбор.

## Автоматическая оценка нового входящего

Запускается только для новых корневых задач во входящих с названием от 3 символов и описанием от 20 символов. Старые задачи, импорт начальной доски и последующие правки не запускают модель автоматически. Дополнение ранее пустого входящего требует ручного запуска. Задача сохраняется независимо от доступности ИИ.

Автозапуск выполняется сервером после успешного сохранения и не зависит от открытой вкладки. Новые задачи ожидают свободный процесс в существующем архиве заданий (статус `waiting`); параллельных обращений модели нет. Перед обработкой проверяется, что задача ещё во входящих и не изменилась, контекст доски обновляется. Отменённые, завершённые и ошибочные задания не перезапускаются при перезагрузке или повторной доставке события. После перезапуска сервера незавершённые задания требуют явного ручного повтора. Число в кнопке — предложение ИИ до человеческого подтверждения; подтверждение не перемещает задачу.


## Лёгкий веб-поиск

Используется существующая авторизация ChatGPT/Codex, без OpenRouter, новых зависимостей и полного Trendwancher. Задание модели ограничивает поиск тремя публичными обезличенными запросами и шестью веб-обращениями, включая открытие страниц; до трёх источников в результате. Адаптер считает уникальные события CLI, учитывает пакетные запросы и останавливает процесс при превышении. Это контроль наблюдаемых событий: обращение, событие которого уже пришло, могло начаться на стороне провайдера. Это не жёсткий денежный лимит. Общий тайм-аут остаётся пять минут; автоматических повторов нет.

Поиск должен находить факты о бизнес-решении и альтернативах, а не только описание метода. Приоритет — датированные первичные материалы последнего года. Анонсы поставщика не доказывают спрос; данные смежного рынка требуют оговорки. Саммари до 500 символов связывает сигнал [1]/[2] с приоритетом и конкретным следующим шагом. Источники и короткие наблюдения скрыты в раскрываемом блоке; новых полей ввода нет.

Источники принимаются только с публичными HTTP(S) URL без учётных данных, сопоставленными с завершёнными веб-событиями CLI (результат поиска или открытие страницы). Это проверка происхождения ссылки, **не автоматическая проверка истинности факта или успешного извлечения всей страницы**. Сигнал и дату публикации формулирует модель; неизвестная дата обозначается явно. Время проверки задаёт сервер. Модель может вернуть недостаточность оснований; отсутствие фактических событий поиска не выдаётся за состоявшийся поиск. Человек остаётся владельцем итоговой оценки.

Пакет связан хешем с режимом поиска, задачей, доской и сохранёнными материалами. Локально сохраняются короткий ответ, источники и счётчики; ответ для проверки хранится в `web-response.json` с правами 0600 внутри закрытого каталога запуска. Не сохраняются полный поток рассуждений, ответы авторизации или stderr. В публичные поисковые запросы запрещено переносить внутренние названия/ID/контекст доски; это инструкция модели, не DLP-фильтр провайдера. Данные задачи и ограниченный контекст доски по-прежнему отправляются OpenAI для анализа.

Документация: [встроенный веб-поиск Codex](https://learn.chatgpt.com/docs/web-search), [параметры поиска](https://learn.chatgpt.com/docs/config-file/config-reference).


Локальная проверка 12.11.2026: реальный запуск на conjoint-задаче завершился с двумя источниками, тремя наблюдаемыми веб-обращениями / тремя запросами и оценкой 6/10. Найден датированный материал Envato от 25.02.2026 о новых тарифах; вывод использует трактовку «шаблоны и графика» как допущение, поскольку категория продукта в задаче не определена. Ссылки и заявленный факт Envato дополнительно просмотрены при проверке. Подтверждения оценки и переноса задачи не выполнялось. Это проверка одного сценария, не доказательство точности прогнозов или качества всех будущих рекомендаций.

## Приоритет без обязательных уточнений и вопрос во время ввода

Новые короткие рекомендации помечены `priorityPolicy=business-v3` (старые `business-v2` читаются без изменений): балл оценивает ценность ближайшего действия для бизнес-цели, внешние сигналы, снятие неопределённости и контекст других задач. Неполнота описания не является автоматическим штрафом. Небольшое исследование может заслуживать высокого приоритета, даже если спрос на продукт пока неизвестен. Модель не должна молча выбирать рынок или требовать от автора обязательного дополнения задачи. Ограничение уверенности остаётся в коротком выводе. Для новых рекомендаций статус `clarify` отображается как «Проверить гипотезу»; старые архивные результаты сохраняют прежнюю подпись.

Во время заполнения формы допускается один необязательный вопрос о существенной неоднозначности продукта/термина. Через 400 мс без изменения текста, при заголовке от 12 символов, отправляется короткий запрос **локальной** модели Qwen3-4B-Instruct-2507 (4 bit, MLX). Название и первые 800 символов контекста остаются на компьютере. У уточнения нет веб-поиска, инструментов, истории диалогов, вложений и контекста доски. Можно ответить, пропустить или сразу сохранить задачу. Ответ сохраняется вместе с вопросом в описании, чтобы его видел и человек, и последующая оценка.

Модель загружается и прогревается один раз при запуске локального сервера. Цель — вопрос за 2–3 секунды после паузы в наборе; запрос ограничен 2,5 секунды, генерация — 80 токенами. Лимит времени сам по себе не гарантирует появление вопроса: при неподготовленной модели, ошибке, занятом обработчике или отсутствии неоднозначности вопрос не показывается. Удалённого запасного вызова нет. Основная оценка после сохранения по-прежнему использует Codex и настроенный лёгкий веб-поиск.

Одновременно выполняется одно уточнение. До трёх попыток на черновик при изменении текста, серверный предел — три на пользователя за 30 секунд. Повтор без изменения текста не отправляется. Пока запрос выполняется, новые символы объединяются в следующий снимок; ответ на устаревший снимок не показывается. Уже показанный вопрос остаётся при дополнении контекста, скрывается при изменении названия. После «Пропустить» новых вопросов этому черновику нет.

Запрос не держит блокировку состояния. Сохранение заполненной задачи и запуск оценки имеют приоритет: незавершённое уточнение отменяется. Закрытие формы/страницы отменяет только несохранённый вопрос; уже запущенная оценка сохранённой задачи продолжает выполняться на сервере. Поздний ответ не меняет задачу. Временные файлы черновика удаляются после завершения или отмены; архив задачи при уточнении не создаётся. Локальный процесс модели получает команды через stdin/stdout, не открывает сетевой порт и закрывается вместе с сервером.

Уточнения включены только вместе с локальной автоматической оценкой в режиме Codex. Существующий критерий автозапуска оценки сохранён: новая входящая задача, заголовок от 3 символов и описание от 20 символов. Отсутствие ответа на уточнение не препятствует оценке такой задачи. Подтверждение балла и перенос остаются действиями человека.

Реальная проверка новой логики на той же conjoint-задаче без ответа на уточнение завершилась оценкой **7/10**: ИИ предложил пилот выбора между одиночным дизайном, набором и отказом от покупки с варьированием цены и лицензии. Вывод явно ограничен трактовкой «шаблоны и графические ассеты». Задача осталась во входящих, подтверждение не выполнялось. Это наблюдение одного ответа модели, а не калибровка шкалы на всей доске.

## Предыдущая политика сохранения исходного смысла (business-v3)

Неуказанный продукт остаётся неуказанным: модель не должна выбирать категорию даже с оговоркой «допущение». Соседние задачи и внешние источники помогают сравнивать и проверять основания, но не задают продукт исходной задачи. Без ответа автора поиск идёт на уровне его формулировки; узкие источники не доказывают спрос на неизвестную категорию. Синтетические тестовые задачи не служат основанием бизнес-приоритета.

Краткий вывод начинается с `N/10 — причина`: ценность исходного исследования для бизнес-цели, необходимость ближайшего действия или отсрочки, применимость внешнего сигнала и ограничение. Шкала, лимиты поиска, длина саммари и подтверждение человеком сохранены. Новая версия политики входит в хеш пакета; история не пересчитывается.

При изменении снимка задачи Codex-разбор не наследует сохранённые материалы от другой версии задачи. Старые источники и отчёты остаются в архиве, но не подставляются в новый запрос.

Предыдущий пример про Figma проверял ответ, введённый ассистентом, и синтетические связанные задачи; он не подтверждает правильность оценки исходной формулировки пользователя. Подставленный ответ и четыре созданные для этого карточки удалены из активных локальных досок с локальными снимками для восстановления. На основной доске восстановлены исходная бизнес-цель и формулировка conjoint-задачи без выбранного ассистентом продукта. Дополнительный тестовый сервер 4344 остановлен; основная доска — 4334.

## Оценка по действующим критериям и пересмотр (criteria-v1)

Новые короткие разборы оценивают исходную задачу на ближайшие 30 дней. Общая цель команды не обязательна. «Фокус» — соответствие текущим интересам и направлению команды; признаки берутся из доступного контекста, не придумываются. Модель возвращает значение, краткое основание и признак предположения для каждого текущего критерия. Сервер проверяет полноту, id, диапазоны и шаги; общий балл модели не принимает. Итог рассчитывает общий с интерфейсом модуль `priority-score.mjs`: среднее нормированных прямых критериев × произведение (1 − value/max) обратных × 10, округление до десятых. Существующая формула и старые оценки сохранены.

Внешние сигналы нужны только при применимости к критерию. Для внутренних улучшений разрешено `not_needed` с нулём веб-вызовов и источников; отсутствие тренда не штрафует задачу. Для поиска прежние лимиты сохраняются. Предположения о величине охвата или усилиях явно помечаются; реальный продукт не додумывается. Короткий вывод объясняет факторы оценки, а не повторяет предложение провести исследование.

В окне остаются краткий вывод, итог и подтверждение. Шесть оснований доступны под «Как рассчитано» (число зависит от настроек доски); источники также свёрнуты. Подтверждение сохраняет предложенные значения критериев. Если человек меняет общий балл, сохраняется явное ручное переопределение; если принимает расчётный итог, задача использует обычную формулу бэклога. Переноса между колонками при подтверждении нет.

Через 30 суток после завершения разбора появляется «Пора пересмотреть» и ↻ рядом с цифрой. Старую рекомендацию нельзя подтвердить после истечения срока; сохранённая оценка остаётся. Пересмотр запускается кнопкой, без таймера платных запусков. У подтверждённых задач бэклога доступна та же кнопка. Новый результат не меняет критерии и подтверждённый итог до явного подтверждения. Дата следующего пересмотра относится к оценке, а не к моменту нажатия «Подтвердить». Изменения задачи/критериев/переданного контекста по-прежнему требуют обновления раньше срока.

Архивные business-v2/business-v3 и старые отчёты доступны без пересчёта. Входящие продолжают оцениваться автоматически после сохранения. Ни веб-поиск, ни оценка через Codex не исполняются внутри Docker без отдельно настроенного подключения; контейнер проверяется на сборку и базовый запуск, реальная интеграция — в локальном preview.

Проверка criteria-v1 на исходной conjoint-задаче 12.11.2026: 42 с, 2 веб-обращения / 1 запрос, применимых внешних оснований не найдено. Оценки 1,5/3; 2/3; 1,5/3; 1,5/3; 4/10; напряг 7/10 дают 1,5/10 по действующей формуле. Все шесть оценок помечены предположениями; на локальной доске только три нерелевантные технические задачи. Это проверка механизма, не подтверждённая человеком приоритизация реального бэклога. Текст исходной задачи и сохранённые оценки при запуске не изменились.


## Неизвестные критерии без числовых догадок (criteria-v2)

Новая политика не заполняет неизвестное средними, нулями или повышенным напрягом. Каждый критерий возвращается как числовое значение с `basis` либо `value: null` с объяснением неизвестного. `basis` указывает на точную цитату из title/body исходной задачи, существующей задачи контекста, сохранённого материала или signal веб-источника. Сервер проверяет существование ссылки, соответствие цитаты переданному фрагменту и происхождение веб-URL из фактических обращений. Это контроль структуры и происхождения, а не автоматическое доказательство истинности источника или применимости суждения модели.

Обычно одну задачу выполняет один человек. Для числового напряга нужны данные об объёме, ресурсах/сроках или сопоставимый выполненный аналог; перечисление этапов метода само по себе не основание. Без них напряг неизвестен и исключён из поправки. Остальные неизвестные критерии также исключены из среднего; отсутствие данных не равно низкой пользе или нулевой вере. Если нет известных прямых критериев, итог null и в интерфейсе «—»; ручной балл остаётся возможен.

При любом пропуске сервер возвращает preliminary=true. В коротком окне — «Частичная оценка · N из M критериев» и «Балл ИИ», при неизвестном обратном критерии — «Напряг не учтён». Число сохраняется даже при одном известном прямом критерии: это среднее известных нормированных значений с известными поправками, а не полная оценка приоритета. Кнопка показывает только звёздочку и балл; во входящих она расположена над действиями «В бэклог» и «В спринт», с выравниванием по правому краю. Частичность и охват остаются в окне и доступном описании кнопки; охват относится только к тому результату, к которому относится её балл. Неизвестные значения в раскрытии — «Не оценено», а не 0. Баллы по разным наборам критериев напрямую не сопоставимы. Ручное изменение и подтверждение доступны как прежде. Кнопка использует розово-перламутровый фон с непрерывным плавным переливом без наведения; при prefers-reduced-motion анимация отключена. Подтверждение сохраняет только известные значения; null не записывается в scores и старые догадки не подмешиваются. Признак предварительности сохраняется вместе с решением человека и виден после перезагрузки/переноса в бэклог. Срок пересмотра 30 дней и отдельное подтверждение нового результата сохранены. Архивные criteria-v1 остаются читаемыми без пересчёта.

Проверка criteria-v2 на исходной conjoint-задаче 12.11.2026: 41 с, один запрос и два веб-обращения. Выхлоп 2/3 подкреплён формулировкой задачи, Вера 5/10 — источником о применимости метода (Sawtooth Software, 20.05.2021). Охват, Фокус, Повестка и Напряг неизвестны. Среднее (2/3 + 5/10) / 2 × 10 = 5,8/10; поправка на напряг отсутствует, итог предварительный, учтено 2 из 6. Методический источник не выдаётся за свежий рыночный тренд, срочность не подтверждена этим поиском. Человеческое подтверждение не выполнялось, доска и исходная формулировка не изменены.

## Поиск актуальности идеи, а не пригодности метода (idea-relevance-v1)

Новые разборы отделяют предмет задачи и принимаемое решение от названия метода. В задаче о продажах цифровых дизайнов поиск направлен на покупки, продажи, выбор предложения, изменения условий и ценности наполнения; conjoint не входит в запросы. Широкий предмет не подменяется Figma, UI-китами, банковскими картами или выбранным ассистентом каналом продаж. Для других задач пример цифровых дизайнов не заменяет их собственный предмет.

В прежнем бюджете (3 запроса, 6 обращений, 3 источника) планируются до двух независимых запросов о рыночных изменениях с предпочтением последних 6–12 месяцев; третий — для уточнения сигнала. Если первый запрос не дал оснований, проверяется другой аспект предмета. Методические справки не повышают Веру в актуальность идеи. Нет применимых оснований — insufficient, без замены на методический источник и без штрафа за неизвестность.

Источники классифицируются как market_change, buyer_behavior или market_conditions и содержат applicability — объяснение связи с задачей и границы переноса. Этот комментарий доступен внутри уже свёрнутых «Источников», основная карточка не усложняется. Схема отклоняет method_reference и пустое пояснение. Семантическая применимость всё ещё требует оценки: наличие допустимого тега не доказывает вывод модели. Общая статистика площадки и анонс инструмента сами по себе не подтверждают спрос на цифровые дизайны.

Маркер evidencePolicy входит в хеш пакета. Материалы старых политик не наследуются новыми запусками; архивы не переписываются. Для проверки направления поиска до трёх фактических запросов (до 400 символов каждый) сохраняются только в локальном закрытом web-response.json. В публичный ответ API эти строки не добавляются. Запросы должны оставаться обезличенными, без внутренних названий и персональных данных.

Локальная проверка на исходной conjoint-задаче 12.11.2026: 49 с, 2 запроса и 3 веб-обращения. Запросы — продажи/покупки digital design assets в 2026, AI/free alternatives, лицензирование и цены; названия conjoint и Figma отсутствовали. Применимых рыночных оснований не получено: sources=[], insufficient. Выхлоп 2/3 подтверждён постановкой задачи, остальные пять критериев неизвестны. Итог 6,7/10 — частичная оценка одного критерия, не повышение подтверждённой перспективности относительно прежних 5,8 (тогда в расчёте была методически обоснованная Вера). Исходная задача и оценки на доске не изменены, подтверждение не выполнено.

## Локальная проверка приоритета MVP команды — concept-mvp-v1

Локальный launcher включает `FUNBAN_TRENDWATCH_CONCEPTS=1`; обычный сервер без флага сохраняет прежний режим criteria-v2. Для локального отката достаточно запустить launcher с `FUNBAN_TRENDWATCH_CONCEPTS=0`: старые отчёты не меняются, новые получат прежнюю методику. Никаких миграций или автоматического пересчёта ранее созданных задач нет.

Новые задания сохраняют профиль команды из `trendwatch-concepts.mjs`: концепции в финтехе, прорывные подходы и полезный передаваемый MVP разработки/исследования/дизайна; РФ как контекст применения, мировой поиск. Профиль — отдельный снимок задания, включённый в хеш; формулировка задачи не дополняется вымышленным продуктом. Учитываются также другие входящие, до 40 задач суммарно с сохранением места для бэклога/выполненных/архива. Изменение выбранного контекста блокирует подтверждение устаревшего результата. Синтетические технические записи запрещено использовать как доказательство бизнес-приоритета.

Балл — целочисленное предварительное суждение о приоритете исходной задачи на 30 дней. Это не среднее шести критериев и не вероятность продаж. Уровни описаны в промпте: 0–2 подтверждённый дубль/отсутствие пользы, 3–4 основания отложить, 5–6 полезная проверка без оснований опередить более важные задачи, 7–8 основания взять ближайшим шагом, 9–10 дополнительно подтверждённая срочность или ограниченное окно возможности. Объяснение должно связывать актуальность, возможность прорыва, передаваемый результат и сравнение с реальными задачами. Сложность и отсутствие уточнений сами по себе не штрафуются. Это пилотная шкала, ещё не откалиброванная на реальном бэклоге команды.

Лимиты сохранены: до 3 запросов, 6 веб-обращений, 3 источников и 5 минут, без автоматических повторов. Цель — 2–3 независимых примера плюс проверка контрсигналов, а не формальное заполнение ссылками. Каждый пример содержит наблюдение, первоисточник данных, прямую применимость или аналогию, связь с приоритетом, ограничение и дату. Перепечатки одного исследования должны иметь один origin. Схема проверяет структуру и происхождение URL; семантическая независимость и истинность источников не доказаны автоматически. Если прямых origin меньше двух или результат insufficient, сервер ограничивает evidenceStrength до limited без механического уменьшения балла. Нехватка применимых примеров остаётся допустимым честным результатом.

В интерфейсе — короткое саммари и один балл. Под «Почему такая оценка» раскрываются обоснование уровня, качество оснований, ограничения и примеры. Человек подтверждает/меняет балл; задача остаётся на месте, существующие значения шести критериев сохраняются. Подтверждённый балл хранится отдельным priorityScore. Через 30 дней требуется пересмотр. Новые и архивные схемы проверяются независимо.

Проверка 13.11.2026 на неизменённой conjoint-задаче: первый запуск (49 с) дал слабые аналогии Canva/Etsy; правила уточнены, чтобы не использовать общий оборот маркетплейса и само наличие роялти как рыночное основание. Один повторный запуск после правки (67 с, 3 запроса, 4 наблюдаемых веб-вызова) дал 6/10 и два источника: опрос Storyblocks от 14.10.2026 и итоговый отчёт CMA от 15.05.2026. Оба обозначены аналогиями, evidenceStrength=limited. Данные о выборе платного контента и генеративных альтернативах проверены по первичным страницам отдельно от запуска модели. Исходный продукт не конкретизирован; оснований для высокого приоритета или доказанного спроса в РФ нет. Рекомендация сохранена в локальном архиве, не подтверждена; состояние доски до/после запуска совпадает. Реальный полный бэклог команды не проверялся: сравнение ограничено локальными данными.


### Регион и читаемое объяснение — regional-signals-v1

Новые локальные задания резервируют один из трёх поисковых запросов для РФ. В `regionalApplicability` сохраняются краткий вывод, статус (местные основания / условный перенос / недостаточно данных) и ссылки только на источники данного отчёта. Статус supported требует хотя бы одну такую ссылку; её содержательную применимость оценивает модель, проверка формата сама по себе этого не доказывает. Иностранные примеры не считаются подтверждением российского спроса; отсутствие местных данных не даёт автоматического штрафа или бонуса. Старые отчёты не переписываются: если регионального блока нет, интерфейс явно сообщает, что отдельной проверки не было.

В саммари нет ссылок и номеров источников. В раскрытии: объяснение балла, применимость к РФ, короткие примеры со ссылками и ограничениями, сравнение с задачами, качество оснований. Сравнение не показывается отдельной рекомендацией снаружи. Весь текст объяснения имеет размер 14 px и межстрочный интервал 1,55; блоки разделены отступами. Перламутровая кнопка сохраняет анимацию и режим reduced-motion. Подтверждение по-прежнему не переносит задачу.

Проверки: 57 серверных, 48 браузерных на трёх экранах; после поправки схемы дополнительно повторены три браузерных региональных сценария. ### Факты и практический эффект — regional-signals-v3

Объяснение начинается с применимого факта и его значения для решения, без обязательного перечисления абстрактных преимуществ MVP. Для коммерческих идей отдельный запрос ищет денежные сигналы: сделки, платящих покупателей, чек, повторные покупки; заявленная готовность платить и цены из каталога не считаются продажами. При неопределённой категории продукта нельзя переносить оборот соседнего рынка на исходную идею.

Для внутренних инструментов разрешён условный сценарий экономии: (время вручную − время с инструментом − проверка/исправления) × повторения за месяц. Если измерений нет, числа явно обозначаются допущениями, учитывается один исполнитель, не придумывается размер команды или ставка. Сценарий не становится доказанным эффектом и не повышает балл автоматически. Это правило генерации, а не автоматическая проверка всех арифметических и смысловых ошибок модели.

Примеры оформлены отдельными блоками на мягком фоне: внутренние отступы 16 px, между блоками 24 px. Кнопка «Обновить рекомендацию» переименована в «Повторить анализ»; подсказка объясняет новый разбор, использование лимитов и сохранение подтверждённой оценки до решения человека.


Реальная проверка 13.11.2026: один запуск 07f351cc-d5e4-478a-b96c-2d005e261271, 73 с, 3 поисковых запроса и 5 наблюдаемых веб-вызовов. Саммари содержит факт из опроса Magram/Литрес (50% заявляют готовность доплатить), второй пример — данные НАФИ о намерении купить и различиях по доходу. Факты проверены по открытым публикациям; реальных сделок исходного продукта не найдено. Предложено 5/10; ранее подтверждённые человеком 6/10 и состояние доски сохранены без изменений. Первоначальная проверка ожидала отсутствие подтверждения и остановилась на устаревшем предположении теста; повторная проверка сохранённого результата без нового вызова модели подтвердила сохранность решения и отображение нового предложения. Пройдены 59 серверных тестов, 48 браузерных, сборка и линтер. Реально проверялся коммерческий conjoint-сценарий; правило условной экономии времени проверено на уровне задания модели, без нового запуска внутренней задачи.

### Комментарии и повторный анализ — regional-signals-v4

Новые concept-mvp-v1 запуски включают текст и дату последних 12 непустых комментариев самой задачи: максимум 4000 символов на комментарий и 16000 суммарно. Авторы и комментарии других задач не отправляются. Признак усечения передаётся модели; отпечаток всех комментариев обнаруживает изменения даже за пределами выбранного фрагмента. Комментарии отправляются в OpenAI через Codex вместе с задачей.

Добавление, изменение или удаление комментария делает прежнюю рекомендацию устаревшей, но не меняет подтверждённый балл и само по себе не запускает модель. После нажатия «Повторить анализ» формируется новый снимок. Подтвердить устаревший результат нельзя. Старый concept-отчёт без снимка комментариев также требует обновления, если комментарии уже есть.

Промпт требует рассматривать комментарии как сведения автора: измерения, расчёты и ссылки могут обосновать приоритет, но просьба повысить балл не является основанием. Инструкции внутри комментариев игнорируются, противоречия отмечаются. При включённом веб-поиске требуется хотя бы один тематический запрос даже при подробном комментарии; not_needed для v4 отклоняется. В публичный поиск промпт запрещает переносить внутренние цифры, идентификаторы, приватные ссылки и текст комментариев — только обезличенную тему. Это инструкция модели, а не гарантированный фильтр секретов: секреты в комментариях хранить нельзя.

В модальном окне убран технический футер и сообщение о ранее сохранённом балле. Поле ввода и действия находятся в стабильной сетке, подсказка об оценке ИИ имеет постоянное место. Проверки используют синтетический CLI и отдельную доску; они подтверждают передачу комментария, поиск, устаревание и сохранность решения, но не качество реального вывода модели.

### Локальная переоценка существующего бэклога

В бэклоге доступны «Переоценить бэклог» и переключатель «По сохранённой оценке / По оценке ИИ». Переоценка включает все задачи со статусом backlog (до 200 за один запуск), даже без описания; модель должна явно ограничивать выводы доступными данными. Во входящих прежнее требование заполненного контекста сохраняется. Индивидуальный анализ теперь доступен и для старых задач бэклога без предыдущего подтверждения ИИ.

POST `/api/backlog/trendwatch` с `{requestId}` подготавливает очередь на одном снимке доски и запускает по одной задаче. На каждую действуют прежние ограничения: до 5 минут, 3 запросов, 6 веб-обращений, без автоматических повторов. Общая стоимость/длительность складывается из всех задач; отдельного денежного лимита эта очередь не добавляет. Повтор requestId не создаёт второй прогон. GET возвращает прогресс и компактный индекс последних рекомендаций; DELETE с `{batchId}` останавливает активную и ожидающие задачи текущего прогона. Остановка доступна его автору. Перезагрузка страницы сохраняет очередь; перезапуск сервера помечает незавершённые запуски прерванными и не возобновляет расход автоматически.

Снимки описания, комментариев и контекста проверяются перед запуском ожидающей задачи. Изменившаяся задача отменяется; готовые устаревшие результаты исключаются из ИИ-сортировки. Оценка 0 является допустимой, отсутствие оценки не превращается в ноль. Ошибка одной задачи не блокирует следующие. Сортировка — представление: оценки, колонки и статусы не изменяются. В матрице порядок меняется внутри колонок; в списке — по всему видимому бэклогу. Сохранённый балл показан отдельно от предложения ИИ; только кнопка подтверждения меняет его.

Рабочую доску напрямую к тестовому серверу не подключать. Для реальных задач нужна отдельная локальная копия JSON из GET `/api/state`, полученная пользователем в уже авторизованном браузере; пароль/куки передавать не нужно. Данные и отчёты хранить внутри игнорируемого `data/` с правами только для владельца. Локальные тесты используют 39 явно синтетических задач и синтетический CLI: это проверка очереди и сохранности оценок, не содержательная оценка реального бэклога.


## Автоматический выбор поиска (adaptive-signals-v1)

Новые разборы concept-mvp-v1 выбирают режим в том же вызове модели, до использования инструментов. `recommendation.assessmentKind`: `bug` (влияние поломки, обходной путь, риск данных), `internal_improvement` (повторяемая польза, чистая экономия времени) или `market_idea` (внешний спрос, продажи, продукт). Решение принимается по смыслу задачи и её комментариев, без отдельного вызова классификатора и обязательных уточнений.

Для первых двух режимов веб-инструменты запрещены инструкцией, результат принимается только с `searchOutcome=not_needed`, пустыми источниками и фактическими нулевыми счётчиками веб-обращений и запросов. Для рыночных идей при включённом поиске требуется хотя бы один запрос; прежние лимиты 3 запроса / 6 обращений / 3 источника сохранены. Это выбор внутри одного модельного вызова: инструменты технически доступны до выбора, нарушение режима отклоняется сервером, но уже выполненный ошибочный запрос вернуть нельзя. Дополнительных автоматических повторов нет.

Дополнение: `approach_research` — исследование нового подхода, технологии или доступных решений, в том числе для внутреннего применения. Для него поиск обязателен при включённом веб-режиме: решения → независимые проверки качества/ограничений → применимость к РФ. Исследование синтетических респондентов относится сюда; автоматизация известного процесса ради измеримой экономии остаётся `internal_improvement` без поиска. Лимиты и подтверждение человеком прежние. Старые ответы продолжают читаться без изменения.

Для внутренних задач скрыт блок применимости к РФ. Неизвестные последствия ошибки и ресурсы не подменяются выдуманными числами; одно название «фиксить Фанбан» не доказывает критичность. Отсутствие рыночных источников само по себе не уменьшает приоритет. Архивные рекомендации сохраняют прежний контракт; новая политика входит в хеш пакета и не наследует источники старого режима. Подтверждённые оценки меняет только человек.


## Пересмотр бэклога и решение лида

Новые задачи остаются во «Входящих» без автоматической ИИ-оценки. Переход выполняет пользователь. В матрице «Не разобрано» показывает задачи без сохранённого балла, с нулём или без выбранной стопки. Предложение ИИ не заменяет сохранённую оценку.

Для активных корневых задач бэклога действует срок 30 дней от последнего решения (подтверждения либо «Оставить как есть»). До первого решения используется первая готовая оценка, а при её отсутствии — дата создания. По истечении срока карточка получает красную рамку и текст «Пересмотреть». Новая ИИ-рекомендация не снимает метку; лид подтверждает новый балл/стопку или сохраняет прежнее решение ещё на 30 дней.

ИИ-пересмотр по сроку отключён: модель запускается только по кнопке пользователя. При прежнем `AUTO=1` сервер раз в минуту обслуживает только бесплатный перенос просроченных карточек; при `AUTO=0` фоновое обслуживание выключено. Счётчики и подсветка работают в обоих случаях. Спринт, выполненные задачи, архив и подзадачи исключены из обслуживания.

При включённом обслуживании через 14 дней после срока пересмотра без решения задача автоматически перемещается в «Не разобрано». Сохранённый балл не меняется, прежняя стопка и дата переноса остаются в серверном `priorityReview`. Повторный перенос в том же цикле не выполняется: ручное возвращение карточки сохраняется. «В “Не разобрано”» — явное несогласие лида, сохраняющее прежний балл и стопку для восстановления.

`adaptive-signals-v2` добавляет предложение стопки, не меняя правил выбора веб-поиска. По умолчанию подтверждение сохраняет текущее положение. Изменение стопки требует выбора в окне и подтверждения; проверяется, что стопка не поменялась в другой вкладке. Ручное перемещение само по себе не делает новую рекомендацию недействительной и не сбрасывает срок пересмотра. Существующие архивы прежних политик читаются без миграции. Даты решений защищены от перезаписи обычным сохранением доски.


## Ценность результата и сравнение материалов adaptive-signals-v3

Новые анализы concept-mvp-v1 используют совместный контекст: до восьми актуальных анализов соседних задач за последние 30 дней, до трёх источников каждого. Отбор учитывает сходство названий/описаний, вид подхода предыдущего анализа и известные связи. Отчёты с изменившимися исходными данными исключаются; демонстрационные карточки не участвуют. Это ограниченная выборка, а не ранжирование всей доски.

Контекст содержит краткий вывод, ценность результата (если есть), силу оснований и источники с датами и ограничениями. Старые баллы, решения лида, авторы, вложения и тексты соседних комментариев не передаются. Используется отпечаток комментариев для проверки актуальности. Новые отчёты соседей не меняют снимок уже выполненного анализа; изменение использованного текста задачи или комментариев делает его устаревшим. В массовой очереди исходные анализы фиксируются до запуска, чтобы порядок выполнения не определял доступные основания. Если готовых материалов нет, сравнение отмечается как недостаточное; дополнительный автоматический исследовательский проход не запускается.

Ответ содержит decisionValue (какое решение станет возможным) и comparison (advantage/equal/insufficient, ссылки на задачи из переданного контекста и краткое объяснение). Генерация ограничена допустимыми ID, а сервер дополнительно проверяет ссылки и хеш контекста. Слабые основания не означают автоматически низкую перспективность; высокий балл остаётся предложением, а не доказательством эффекта. Условную пользу нужно обозначать как гипотезу.

В окне рекомендации надёжность оснований показана отдельной короткой строкой; ценность результата и очередность находятся внутри «Почему такая оценка». При равных баллах сортировка ИИ сохраняет порядок доски вместо алфавита. Сохранённые оценки, стопки и счётчики не изменяются новым анализом. Старые отчёты читаются по прежним схемам, без миграции.

Калибровка на решениях лида и вывод приоритетов директоров не внедрены. Сравнение объясняет предложение для человека; оно не создаёт доказанную глобальную очередь и не требует искусственно разных баллов.

## Согласованность сравнения adaptive-signals-v4

Новые анализы получают `aiScore` соседних готовых рекомендаций вместе с их основаниями. Это предложения ИИ; подтверждённые лидом баллы и его решения в контекст сравнения не добавляются. Причина изменения: в v3 независимое число 7 могло сопровождаться заявлением о равенстве с задачей на 6.

Балл и сравнение теперь должны выражать одно решение: `advantage` требует большего балла, `equal` — одинакового, `behind` — меньшего, чем у каждого указанного соседа. `insufficient` означает отсутствие обоснованного сравнения, а не равный приоритет. Промпт требует сначала сопоставить пользу, затем согласовать балл и объяснение; сервер проверяет численное соответствие и отклоняет противоречивый ответ без изменения доски и без автоматического платного повтора. Проверка чисел не является доказательством содержательности текста: это отдельно проверяется на примерах.

Сравнение привязано к использованным предложениям ИИ. Если у упомянутого соседа позже изменился актуальный балл, `comparisonCurrent=false`: интерфейс скрывает устаревшее объяснение очередности и предлагает повторить анализ. Собственный предложенный балл сохраняется. Новый отчёт с тем же баллом не устаревает сравнение. Отчёты v3 и прежних версий остаются читаемыми без миграции.

Равные баллы допустимы, их порядок остаётся порядком доски. Неизвестные ресурсы не штрафуются, ложный победитель не назначается. Формула сохранённых оценок, стопки, подтверждение лидом и сроки пересмотра не изменены.


## Подтверждение входящих — 14.11.2026

Актуальный сценарий заменяет прежнее отдельное подтверждение без переноса: во входящих «Подтвердить» атомарно сохраняет оценку лида и переводит задачу в бэклог. До нажатия изменение числа остаётся черновиком. При ошибке сохранения окно остаётся открытым, задача и прежний балл не меняются; при успехе окно закрывается. Подтверждение в самом бэклоге меняет балл без перемещения между колонками, кроме прежнего правила нулевого приоритета.

Перламутровая кнопка всегда относится к предложению ИИ, отдельно от подтверждённого приоритета. Например, ИИ 7 и решение лида 9 отображаются как ✦ 7 рядом с 9 в бэклоге. Редактирование и подтверждение не переписывают рекомендацию; при устаревании число сохраняется с соответствующей подписью. Новое предложение появляется только после повторного анализа. Неизвестный балл ИИ остаётся «—» и не подменяется оценкой человека.
