# Подключение OpenRouter локально

Для серверного развёртывания используйте [отдельную инструкцию](openrouter-server.md): локальный preview не предназначен для публикации.

Подготовлен отдельный адаптер лёгкой оценки. Он использует ту же задачу, комментарии, профиль команды, контекст доски, схему ответа и проверки, что и текущий режим Codex. Полный Trendwancher не запускается. Текущий экземпляр Funban на 4338 остаётся в режиме Codex до явного переключения.

В режиме OpenRouter необязательный вопрос при вводе также выполняется через API при `FUNBAN_TRENDWATCH_AUTO=1`, без Python/MLX и поиска. Можно указать отдельную быструю модель `FUNBAN_OPENROUTER_CLARIFY_MODEL`; по умолчанию используется основная. Лимит — 128 выходных токенов и 2300 мс на запрос с проверкой бюджета, без повторов. Отправляются только название и первые 800 символов контекста черновика. При задержке задача сохраняется без вопроса; качество и время ответа проверяются отдельно с реальной моделью.

## Настройка

1. Создайте **отдельный ключ OpenRouter** с конечным лимитом расходов, например $5. Ключ без лимита, с лимитом выше настройки или без остатка не допускается к генерации. Это лимит ключа, а не цена одной рекомендации; не используйте этот ключ в других приложениях.
2. В корне репозитория выполните `cp .env.example .env.openrouter.local` и `chmod 600 .env.openrouter.local`. Заполните файл в локальном редакторе. Ключ не нужно присылать в чат.
3. Укажите `OPENROUTER_API_KEY` и `FUNBAN_OPENROUTER_MODEL` — точный ID модели с поддержкой Responses API, JSON Schema и инструментов. Модель автоматически не выбирается и не подменяется. `:online` и `openrouter/auto` запрещены, чтобы не обходить управление поиском и моделью.
4. Выполните `npm run check:openrouter`. Проверка не обращается в сеть и не показывает ключ. Она проверяет форму настроек, но не доступность модели или баланс.
5. После завершения текущих анализов остановите локальный preview на 4338 и запустите `npm run dev:openrouter`. Не запускайте вторую версию на другом порту. Включается только локальная доска с mock portal; рабочая доска не подключается.
6. Для первой проверки вручную запустите **одну** карточку. Это уже платный запрос. Автоматические оценки и месячный пересмотр по умолчанию выключены (`FUNBAN_TRENDWATCH_AUTO=0`). После проверки их можно включить этой настройкой, учитывая возможную очередь просроченных задач.

Откат: остановить preview и запустить `FUNBAN_TRENDWATCH_MODE=codex FUNBAN_TRENDWATCH_AUTO=0 npm run dev:local`. Сохранённые баллы и архив рекомендаций остаются на месте. Не запускайте два backend с одним файлом состояния.

## Поведение и ограничения

- Один запрос генерации на анализ, без автоматических повторов. Перед ним — read-only запрос сведений о лимите ключа. Не более 4096 выходных токенов по умолчанию, 180 секунд на весь запуск; вход ограничен 100 КБ. Верхние границы конфигурации: 8192 токена и 240 секунд.
- Модель выбирает режим по существующим правилам. Баги и обычные внутренние улучшения должны вернуть результат без поиска. Если модель всё же использовала поиск для внутренней задачи, результат отклоняется. Исследование нового подхода требует поиска; одного названия «внутренний» недостаточно для его отключения.
- Рыночные идеи и новые подходы: встроенный `openrouter:web_search`, явно заданный Exa fast, до трёх поисков и девяти результатов, до трёх источников в рекомендации. Используются выдержки поиска; полное чтение каждой страницы не заявляется.
- Число поисков берётся из usage провайдера, ссылки сверяются с его `url_citation` annotations. Ссылки, написанные самой моделью, не подтверждают поиск. Отсутствие этих метаданных, неверный JSON, несогласованное сравнение или превышение лимитов дают ошибку, а не фиктивную оценку.
- Цена зависит от модели, её внутренних шагов и поиска. Ограничения токенов/времени не являются точной долларовой сметой. Жёсткую границу расходов обеспечивает лимит отдельного ключа у провайдера; уже выполненная работа может быть оплачена и при отмене/ошибке ответа.
- Ключ передаётся только сервером в заголовке запроса на фиксированный HTTPS endpoint OpenRouter. Redirect запрещён. `.env*` исключены из Git и Docker, кроме пустого шаблона `.env.example`. В публичные ошибки не попадают ответы провайдера или ключи.
- Текст задачи, комментариев и контекст доски передаются через OpenRouter выбранному провайдеру модели. Поисковику должна передаваться только обезличенная публичная тема. Запрошены `store:false` и `provider.data_collection=deny`; это не заявление, что данные вообще не покидают компьютер или что у всех участников нулевое хранение.
- Локальное уточнение при вводе остаётся отдельным офлайн-механизмом. OpenRouter не запускается на каждое нажатие клавиши.
- Новая ИИ-оценка хранится отдельно. Сохранённый балл меняется только после подтверждения человека. Подтверждение во входящих переносит карточку в бэклог с баллом человека; балл ИИ сохраняется до следующего анализа.

## Что проверено до подключения

Тесты используют синтетические HTTP-ответы: режим без поиска, подтверждение источников, неверные ответы, ошибки авторизации/баланса/лимитов, тайм-аут, отмена и сохранность прежней оценки. Реальный ключ, конкретная модель и платный запрос в рамках подготовки не проверялись. Server tools OpenRouter находятся в beta: первый живой запуск должен подтвердить совместимость их ответа с валидатором.

Документация провайдера: [Web Search Server Tool](https://openrouter.ai/docs/guides/features/server-tools/web-search), [лимиты ключа](https://openrouter.ai/docs/api/reference/limits). Для Docker подготовлен отдельный явно включаемый [серверный режим](openrouter-server.md). Эта локальная инструкция не включает развёртывание или запуск на рабочей доске.
